# Versioned forms and reviewed AI correspondence Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publish configurable, versioned feedback forms and operate evidence-backed AI classification, reviewed replies, and explicitly controlled template auto-replies.

**Architecture:** Keep form, identity, permission, prompt, policy, durable work and SMTP orchestration in Feedback Inbox. Isolate provider transports and request/result/error contracts in reusable local `crates/ai-kit`, with no domain/database dependencies. Use SQLite transactions for immutable publication, idempotency, claims, approvals and quotas, and retain nginx as the sole public app entry.

**Tech Stack:** Existing Rust 2021, axum 0.8, SQLx 0.8 SQLite, reqwest 0.12, lettre 0.11, React 19, TypeScript, Tailwind, Vitest; add narrowly scoped AES-GCM/HMAC/base64/URL and JSON Schema validation dependencies where needed.

**Spec:** [2026-11-28-forms-ai-design.md](../specs/2026-11-28-forms-ai-design.md)

## Global Constraints

- AI is optional; no provider configuration or deployment secret is required for existing form and inbox operations.
- Provider credentials stay server-side; the browser never receives a saved secret, signing key after creation, or provider authorization header.
- Public intake accepts at most 65,536 bytes; no file upload is supported.
- All persisted timestamps use UTC; quota days are UTC and are labeled UTC in the UI.
- Admin/API pages retain `X-Frame-Options: DENY`; framing is enabled only for the dedicated public embed response.
- Existing SQLite data and existing read-only API/MCP authorization must survive migration.
- Generated snippets are deterministic checked templates, never model-generated integration code.
- Automated verification uses disposable databases, local fixture model providers, and local Mailpit only.
- Resource bounds during implementation: `CARGO_BUILD_JOBS=2 CARGO_PROFILE_DEV_DEBUG=0 CARGO_PROFILE_TEST_DEBUG=0`; Vitest maximum 2 workers. Coordinate Docker image builds with the root worker before starting.
- Local scoped commits are authorized after the relevant checks. Do not push or open a PR from this worker; root coordinates delivery.

## Review Focus

- Existing origin-less legacy installs and new empty allowlists must have different explicit behavior; task 3 pins migration and browser cases.
- Published key/type/option changes must not reinterpret previous answers or silently drop required controls; tasks 1–2 pin version/render parity.
- A member/provider/policy/knowledge change during a queued or running generation must stop stale egress/results; tasks 7–8 pin authority and version races.
- Cancellation, retries and SMTP ambiguity must not create duplicate visitor messages; tasks 6 and 10–11 pin competing claims and unknown outcomes.
- Anonymous contacts, synthetic test submissions and model-declared confidence must never bypass automatic policy gates; task 11 pins every gate.
